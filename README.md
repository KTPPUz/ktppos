# ktppos — BAAN POS

Interactive mockup ระบบขายหน้าร้านสำหรับร้านค้าปลีกทั่วไป อ้างอิง POS SYSTEM PRD v1.0 วันที่ 22 ตุลาคม 2026 รองรับภาษาไทย สกุลเงินบาท และหน้าจอเดสก์ท็อป/แท็บเล็ต พร้อมปรับ layout สำหรับจอเล็ก

ใช้ข้อมูลจำลองในเบราว์เซอร์สำหรับทดลองขั้นตอนทำงาน ไม่มี Backend หรือการรับชำระเงินจริง

## เปิดใช้งาน

- [เว็บต้นแบบออนไลน์](https://baan-shop-pos-kp-2026.orange-0321.chatgpt.site) — เผยแพร่แบบส่วนตัว อาจต้องเข้าสู่บัญชีเจ้าของ
- Local: <http://localhost:8087> หลังเปิดเซิร์ฟเวอร์ตามขั้นตอนด้านล่าง
- [Design handoff](dist/handoff.html) — Sitemap, Wireframe, รายการหน้าจอ, User flows และ Design tokens

## วิธีรันบนเครื่อง

ต้องมี Python 3 และเบราว์เซอร์รุ่นปัจจุบัน ส่วน Node.js ใช้เฉพาะเมื่อต้องการรันชุดตรวจสอบ แนะนำ Node.js 18 ขึ้นไป

รันจาก root ของโปรเจกต์:

```sh
cd /Applications/MAMP/htdocs/pos-mockup
python3 -m http.server 8087 --bind 127.0.0.1 --directory dist
```

เปิด <http://localhost:8087> และหยุดเซิร์ฟเวอร์ด้วย `Ctrl+C` หากพอร์ตถูกใช้งานอยู่แล้ว ให้ใช้เซิร์ฟเวอร์เดิมหรือเปลี่ยนหมายเลขพอร์ต

หากใช้ MAMP ให้เปิด Apache และเข้า URL ตามพอร์ตที่ตั้งค่าไว้ เช่น <http://localhost:8888/pos-mockup/dist/> เมื่อ Document Root เป็น `/Applications/MAMP/htdocs`

Google Fonts ต้องใช้อินเทอร์เน็ต หากโหลดไม่ได้ ระบบจะใช้ฟอนต์สำรอง

## ทดลองใช้งาน

เริ่มต้นด้วยบทบาท `Owner / Admin` สาขาอารีย์ กะเปิดอยู่ และมีสินค้าตัวอย่าง 12 รายการ พร้อมนมและขนมปังในตะกร้ารวม 209 บาท

### ขายสินค้าและรับชำระ

1. เลือกสินค้า หรือค้นหา `SKU-001` / บาร์โค้ด `8850000000001`
2. ปรับจำนวน เพิ่มสมาชิก หรือกำหนดส่วนลด
3. กด **ชำระเงิน** เลือกวิธีชำระ และระบุเงินรับสำหรับเงินสด
4. กด **ยืนยันรับชำระ** เพื่อดูใบเสร็จ
5. ตรวจสอบบิลที่ประวัติการขาย และยอดสินค้าที่คลังสินค้า

เลือก **จำลองการชำระเงินล้มเหลว** ในหน้าชำระเงินเพื่อทดลอง error โดยไม่บันทึกการขายหรือตัดสต๊อก

### คืนสินค้า

1. เปิดประวัติการขาย แล้วเลือก **คืนสินค้า** ที่บิลสำเร็จ
2. ใช้บทบาท Owner / Admin, Store Manager หรือ HQ / Operations
3. ระบุเหตุผลและยืนยันคืนเงินทั้งบิล
4. ระบบคืนสต๊อกและปรับแต้มสมาชิก พร้อมบันทึกผู้อนุมัติในข้อมูลบิล

### รับเข้าและโอนสินค้า

1. เปิดคลังสินค้า เลือก **รับเข้า / ปรับยอด** ระบุจำนวนและเหตุผล แล้วบันทึก
2. หรือเปิดสาขาและการโอน เลือก **สร้างใบโอนสินค้า**
3. เลือกสินค้า สาขาปลายทาง และจำนวน ระบบหักสินค้าจากต้นทางเมื่อสร้างใบโอน
4. สลับเป็นสาขาปลายทาง แล้วกด **ยืนยันรับ** เพื่อเพิ่มสต๊อกปลายทาง

### ทดลองสิทธิ์

กดโปรไฟล์มุมล่างซ้ายเพื่อสลับบทบาทและสาขา

| บทบาท | สิทธิ์ในต้นแบบ |
| --- | --- |
| Cashier | ขาย พักบิล ดูสินค้า/สต๊อก ประวัติ ลูกค้า และโปรโมชัน; แก้ไขสินค้า ปรับสต๊อก ส่วนลด และคืนเงินไม่ได้ |
| Store Manager | จัดการการขาย สินค้า สต๊อก ลูกค้า โอนสาขา รายงาน และ Audit |
| Owner / Admin | ทุกหน้าจอ รวมตั้งค่าร้านและพนักงาน |
| HQ / Operations | จัดการร้านและสาขา ดูรายงานรวมทุกสาขา; ไม่มีสิทธิ์ตั้งค่าร้านหรือพนักงาน |
| Auditor / Finance | ดูภาพรวม รายงาน ประวัติการขาย และ Audit |

สิทธิ์เป็นการจำลองฝั่ง Frontend สำหรับทดสอบ UX การเปลี่ยนบทบาทพนักงานในตารางไม่เปลี่ยนบทบาทของเซสชันปัจจุบัน ต้องสลับที่โปรไฟล์

## กฎการคำนวณและข้อมูล

- ราคาสินค้ารวม VAT เริ่มต้น 7% ปรับได้ในตั้งค่าร้าน
- ยอดสุทธิ = ยอดรวมสินค้า − ส่วนลด โดยส่วนลดที่นำมาคำนวณไม่เกินยอดรวมสินค้า
- VAT ที่รวมในราคา = ยอดสุทธิ × อัตราภาษี ÷ (100 + อัตราภาษี) ปัดเศษ 2 ตำแหน่ง
- เงินทอน = เงินรับ − ยอดสุทธิ
- สมาชิกได้รับ 1 แต้มต่อยอดซื้อครบ 25 บาทในแต่ละบิล
- ขายสำเร็จจึงตัดสต๊อก พักบิลหรือจ่ายล้มเหลวไม่ตัดสต๊อก
- การคืนสินค้าในต้นแบบรองรับคืนทั้งบิล และป้องกันคืนบิลเดิมซ้ำ
- ยอดรายงานไม่รวมบิลที่คืนเงินแล้ว ใช้วันที่ตามเขตเวลา `Asia/Bangkok`

## ตรวจสอบการทำงาน

รันจาก root ของโปรเจกต์:

```sh
node --check dist/app.js
node verify.cjs
```

ชุดตรวจสอบครอบคลุมการ render 12 เมนู ยอดรวม/VAT สินค้าไม่พอ พักบิล เงินรับไม่ครบ จ่ายล้มเหลว ขายสำเร็จ/เงินทอน คืนเงิน การแยกสต๊อกสาขา โอน/รับสินค้า สิทธิ์ และค้นหา SKU/Barcode

การทดสอบใช้ DOM จำลองใน Node.js ไม่ใช่ browser E2E และไม่ตรวจหน้าตา การจัดวาง การพิมพ์ หรือการใช้งานผ่านอุปกรณ์จริง

## การเก็บและล้างข้อมูล

ข้อมูลเก็บใน `localStorage` คีย์ `baan-pos-v1` แยกตาม origin ของเว็บ ดังนั้น localhost ต่างพอร์ต, `localhost` กับ `127.0.0.1` และเว็บออนไลน์จะมีข้อมูลคนละชุด ไม่มีการซิงก์ระหว่างเครื่องหรือเบราว์เซอร์

หากต้องการเริ่มข้อมูลตัวอย่างใหม่ ให้เปิด Developer Console ของเว็บนั้นแล้วรันคำสั่งต่อไปนี้ **คำสั่งนี้ลบข้อมูลจำลองที่เคยทำไว้ทั้งหมดบน origin นั้น**:

```js
localStorage.removeItem('baan-pos-v1');
location.reload();
```

## ข้อจำกัดของต้นแบบ

- ไม่มี Backend API, ฐานข้อมูลกลาง, authentication จริง หรือ server-side RBAC
- QR และบัตรเป็นการจำลอง ไม่มี Payment gateway หรือการรับเงินจริง
- คืนสินค้าได้ทั้งบิล ยังไม่รองรับคืนบางรายการหรือแบ่งชำระ
- สถานะเปิด/ปิดกะเป็นค่าเดียวในข้อมูลต้นแบบ ไม่ได้แยกกะต่อสาขาหรือเครื่อง
- ข้อมูลสินค้า ราคา ลูกค้า และพนักงานใช้ร่วมกันในต้นแบบ ส่วนสต๊อกและรายการขายแยกตามสาขา
- Audit เก็บในเบราว์เซอร์และเปลี่ยนแปลงได้ ไม่ใช่ audit trail สำหรับระบบใช้งานจริง
- ใบเสร็จพิมพ์ผ่านเบราว์เซอร์ ไม่มีการเชื่อมเครื่องพิมพ์ POS หรือระบบ e-Tax
- มี offline warning และใช้ข้อมูลที่โหลดแล้วได้ แต่ไม่มี Service Worker, offline cache หรือระบบซิงก์
- ตัวเลขและข้อความบางส่วน เช่น วันที่บน header และเวลาเปิดกะ เป็นข้อมูลสาธิตคงที่

หากพัฒนาต่อเป็นระบบใช้งานจริง ต้องเพิ่ม Backend, authentication, สิทธิ์และ tenant/branch isolation ฝั่งเซิร์ฟเวอร์, database transactions, payment idempotency และการเชื่อมอุปกรณ์ตามขอบเขตธุรกิจ
